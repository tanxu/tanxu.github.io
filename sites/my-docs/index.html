my-docs / index.html

概述

这个页面演示的是一个独立文档站在同一个域名下的落位方式。它本身是手写的静态 HTML，但排版刻意贴近 VitePress —— 左边深色目录、右边正文、代码块 + 表格 + 提示框。

访问路径是 <站点根>/my-docs/。站点根在你的用户页上是 https://<用户名>.github.io/，所以完整地址是 https://<用户名>.github.io/my-docs/。

布局与落位

源文件在仓库中的位置和它最终被发布到哪里，是两件事：

阶段位置
源文件sites/my-docs/index.html
构建后dist/my-docs/index.html
线上访问<站点根>/my-docs/

构建脚本做的事只有一件：把 sites/ 下的每个子目录原样复制到 dist/ 下的同名目录。所以这类站点不需要任何构建配置， 也不参与微前端的装载流程。

接入自建文档

想换成真正的 VitePress，把目录替换成它的构建产物即可：

# VitePress 配置里把 base 指向子路径
echo "export default { base: '/my-docs/' }" > .vitepress/config.mts

# 构建产物直接输出到 sites/my-docs/
vitepress build --outDir sites/my-docs

注意 base 必须首尾都带斜杠，且与访问路径上的目录名完全一致， 否则资源会 404 —— 这是子路径部署最常见的坑。

上线前清单

1. 确认 sites/<name>/index.html 存在（构建脚本会校验）；
2. 确认站点内部引用资源用的是相对路径，或已按子路径配好 base；
3. 确认没有和 Shell 的根路径发生冲突。

第 3 条一般不用担心：Shell 用的是 hash 路由（地址形如 /#/react-19/todo），路径部分永远是 /，不会和任何子目录抢位置。
