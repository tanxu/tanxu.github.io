## 微前端模板项目初始化（D:\workbuddy-微前端）

### 需求
用户要一个部署到 GitHub Pages 的微前端架构模板：TypeScript、多技术栈独立子项目（原生 JS / React 19 / Vue 3）、运行时隔离 + 各自独立的状态管理。先做方案评估，用户确认后再生成模板。

### 方案评估结论（用户确认）
四项全部选择推荐项：
1. **集成方案**：Shell + 原生 ESM 契约（动态 `import()` 子应用入口 + Shadow DOM 挂载），不用 Module Federation / qiankun / iframe
2. **隔离级别**：Shadow DOM（样式）+ ESM 模块作用域（JS），**不做 Proxy 沙箱**，靠架构约定
3. **仓库形态**：单仓 monorepo（npm/pnpm workspace）单站点，子应用部署在 `/apps/<id>/` 子路径
4. **路由**：hash 路由 `#/<appId>/<内部路由>`，规避 GitHub Pages 无服务端路由的 404 问题

### 已交付内容
- `packages/contract`：纯类型契约（`MfeBus` / `MfeMountContext` / `MicroAppModule` / `AppManifest`），只允许 `import type`
- `shell/`：hash 路由 + 装载器（manifest → 样式 → 动态 import → mount）+ CustomEvent 事件总线 + dev 期 `/apps` 静态中间件
- `apps/vanilla`（自研 EventTarget store）、`apps/react-19`（Zustand + React 19 Action 表单）、`apps/vue-3`（Pinia，响应式 routeState 传参）
- `tools/`：`mfe-manifest.ts`（构建期生成 manifest.json）、`dev-host.ts`（独立开发的 Shadow DOM 宿主）、`workspace.mjs`
- `scripts/`：build / dev / preview / typecheck / clean，包管理器无关（探测 npm_config_user_agent）
- `.github/workflows/deploy.yml`：npm ci → typecheck → build → 部署 dist/ 到 Pages

### 踩过的坑（重要）
1. **Vite lib 模式不替换 `process.env.NODE_ENV`** → React/Vue 会打进 development 版本。
   修复：子应用 `define: command === 'build' ? { 'process.env.NODE_ENV': '"production"' } : {}`。
   效果：React 产物 1076KB → 344KB。
2. **相对 outDir 的层级算错**：`shell/vite.config.ts` 用 `'../../dist'` 会解析到 `D:/dist`（shell 只有一层深）。
   修复：shell 用 `'../dist'`，子应用（apps/<name>/ 两层）用 `'../../dist/apps/<name>'`。
3. **不要在同一条消息里对同一个文件发两次 Edit**：会互相覆盖，导致改动丢失。
4. **TS 泛型事件总线**：`once` 内部把 `MfeEventHandler<T>` 当 `MfeEvent<unknown>` 调用会报 TS2345，
   需显式断言为 `(event: MfeEvent<unknown>) => void`。
5. 沙箱内 Bash 工具不可用（缺 coreutils），改用 PowerShell；PowerShell 工具的 stdout 不返回，需重定向到文件再读。

### 运行时冒烟测试（headless Chrome + CDP）发现并修复的 2 个真实 bug
1. **ShadowRoot 内脱离文档的 `<link rel=stylesheet>` 不会发起请求**，onload 永不触发 → 整个激活流程挂死，
   状态一直停在"加载中"且无任何报错。
   修复：`doActivate` 里先把宿主节点 `attach` 进文档（此时 display:none，不会闪出半成品）再下载；
   `loadStyle` 额外加 5s 兜底超时。
2. **事件总线发送方标识错误**：原实现 Shell 只建一份 bus 且 `getSource()` 固定返回 'shell'，
   子应用 emit 时 source 也是 'shell'，导致所有事件被"自己发的不回传"规则吞掉。
   修复：改为**每个子应用一份总线门面**（`createBus(() => def.id)`），共用 document 上的同一个通道，
   但各自持有独立订阅表与发送方标识。

### 踩坑补充
5. **子应用非激活状态收不到事件**：因为 unmount 必须取消订阅。这是设计语义，已写入 README。

## 部署上线排障（用户推送到 tanxu/tanxu.github.io 后）
- 症状：访问 `https://tanxu.github.io/` 显示 README 内容而非微前端应用。
- 诊断（curl GitHub API 免认证可查公开仓库）：
  - 线上首页 HTML 含 `generator=Jekyll v3.10.0`、`site_name=谭旭` → 是 Jekyll 产物；
  - Actions 列表同时存在两条成功的 run：`Deploy to GitHub Pages`（push，我们的）与
    `pages build and deployment`（event=`dynamic`，GitHub 内置 Jekyll）→ 说明仓库 Pages 来源是 branch。
- 根因：**仓库 Pages 的 Source 仍是 "Deploy from a branch"**，而仓库根目录最上层只有 README.md、
  没有 index.html，Jekyll 直接把 README 渲染成首页；我们的 dist/ 从未被采用。
  这是仓库设置问题，不是模板代码问题，代码层面无法修改。
- 处理：
  1. `.github/workflows/deploy.yml` 的 configure-pages 加 `enablement: true`（新建仓库首次部署兜底）；
  2. README 第 7 节加强警告 + 验证判据；
  3. 用户需在 Settings → Pages → Source 手动改为 GitHub Actions，再 Run workflow 重跑一次。
- 教训：交付含 CI 部署的模板时，首次部署必须显式提醒「Pages Source 要选 GitHub Actions」，
  并给出判据（线上 HTML 含 `id="mfe-stage"` / Actions 无 `pages build and deployment`），
  否则 `<user>.github.io` 用户页仓库极易出现"README 代替应用"的现象。

## 事件总线重做 + pnpm 迁移（第二轮，站点已上线）

### 「广播到其他子应用」重做为离线消息补齐
- 用户反馈：点了广播，其他子应用界面毫无变化。
- 根因：同一时刻只有一个子应用挂载（切走即 unmount、取消订阅），
  广播发出时其他子应用根本不在线，等切过去事件早已消失。
  单挂载架构下「跨应用实时通信」不可能发生，原按钮约等于无用。
- 重做为「离线消息补齐」模型：
  1. Shell 用 `bus.on('*')` 通配订阅缓存最近 20 条事件，页脚新增事件总线面板实时展示（可清空）；
  2. 子应用挂载后延迟 50ms 补投它离线期间错过的，标记 `replayed: true`；
  3. 每实例一个 lastDeliveredTs 水位线，只补投「上次离线之后」的事件，切来切去不重复；
  4. 三个子应用 handler 识别 replayed，日志显示「离线期间：xxx 曾广播计数 n」。
- **关键时序坑：React 的 useEffect 由调度器异步 flush**，mount() 返回后同步回放会赶在
  订阅注册之前被静默丢弃 —— 必须延后一个事件循环（50ms setTimeout）再投递。
- 契约新增 `MfeEvent.replayed?`；shell 内部 `BusFacade` 类型带 `replay`，
  子应用拿到的 `ctx.bus` 仍是干净的 `MfeBus`。
- 验证：headless Chrome + CDP 冒烟 9 项断言 ALL PASS（离线回放、不重复回放、
  不收到自己发的事件、面板即时更新、清空、无运行时异常）。

### pnpm 迁移（npm → pnpm 12.4.2）
- 各子包 package.json 显式声明 `"@mfe/contract": "workspace:*"` —— pnpm 严格模式必需，
  否则 tsc 报 TS2307 Cannot find module '@mfe/contract'。
- 根 package.json：删 workspaces 数组、加 packageManager 字段、
  devDependencies 补 vite + @types/node（`tools/mfe-manifest.ts` 被四个包共享，
  pnpm 下没人替 tools/ 提升依赖，必须根声明）。
- **pnpm 11 起 `onlyBuiltDependencies` 已移除，改为 `allowBuilds`（map 形式：包名 → true/false）**，
  且 `strictDepBuilds` 默认 true：未审查的 postinstall 让 install 直接报 ERR_PNPM_IGNORED_BUILDS
  硬失败（pnpm 10 时代只是告警）。pnpm 会自动往 pnpm-workspace.yaml 写占位符
  `包名: set this to true or false`，手动改成 true 即可。模板放行 esbuild + vue-demi。

  setup-node cache: pnpm → `pnpm install --frozen-lockfile`；pnpm 必须在 setup-node **之前**装。

- 迁移中暴露的 TS 细节：函数声明（非箭头函数）内不保留外层 const 的 narrowing，
